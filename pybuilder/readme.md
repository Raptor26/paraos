
# Регулярные выражения
`Pybuilder` поддерживает регулярные выражения, что позволяет гибко задавать множества конкретных пресетов с помощью `шаблонов`.  
Ознакомиться с правилами задания шаблонов регулярных выражений, а также проверить свои шаблоны можно по [данной ссылке](https://regex101.com/).

# Описание поддерживаемых аргументов

`--exclude <preset_regex>`  
Исключить заданные пресеты из списка для сборки и тестирования.  
Сокращение: `-e`.

`--include <preset_regex>`  
Включить только указанные пресеты в список для сборки и тестирования.  
Для того, чтобы выбрать все доступные пресеты, можно не указывать данный аргумент в терминале при вызове `pybuilder`.  
Сокращение: `-i`.

**ВНИМАНИЕ**
В текущей реализации не предусмотрена возможность одновременного задания списка включений `--include` и исключений `--exclude`!

`--build-only <preset_regex>`  
Указать для каких пресетов необходимо выполнить только сборку без запуска тестирования. Данный список формируется из множества пресетов `include` с учётом вычитания множества `exclude`.  
Сокращение: `-b`.

`--cmake-project-dir <project_path>`  
Указание пути до проекта.  
Сокращение: `-d`.

`--ctest-options <options>`  
Указание флагов ctest, с которыми необходимо запускать тестирование.  
Сокращение: `-t`.

# Запуск

Рассмотрим примеры вызова скрипта `pybuilder`:
```bash
python3 pybuilder/pycmakebuilder.py 
    -d="${PWD}" 
    --ctest-options="--output-on-failure 
                     --stop-on-failure 
                     --schedule-random
                     --repeat-until-fail 300
                     --timeout 20
                     -L [stress]" 
    -e="trace*|docker*|clang_tidy*|freertos*"
```
В примере выше выполняется вызов `pybuilder` со следующими аргументами:  
1. `(-d)`: Каталог проекта - текущий каталог.
2. `(--ctest-options)`: Указаны необходимые флаги для `ctest`.
3. `(-e)`: Указано множество `exclude`, в которое попадают пресеты, в названии которых содержится слово _trace_ `или` _docker_ `или` _clang_tidy_ `или` freertos. В шаблонах регулярных выражений символ `|` означает `или`.

Аргумент `--include` не указан, поэтому множество `include` изначально будет состоять из всех доступных пресетов. Данное множество, затем, будет скорректировано с помощью множества `exclude`.

Рассмотрим ещё один пример:
```bash
python3 pybuilder/pycmakebuilder.py 
    -d="${PWD}" 
    --ctest-options="--output-on-failure 
                     --stop-on-failure 
                     --schedule-random
                     -j1
                     --repeat-until-fail 75
                     --timeout 20
                     -L [stress]" 
    -i="freertos*(?!.*tidy)"
    -b="trace*"
```
Данный пример содержит следующие аргументы:
1. `(-d)`: Рабочий каталог.
2. `(--ctest-options)`: Флаги `ctest`.
3. `(-i)`: Множество `include`, заданное с помощью шаблона регулярных выражений. Данный шаблон означает, что необходимо включить в тестирование все пресеты, в названии которых есть слово _freertos_, `но` нет слова _tidy_.
4. `(-b)`: Задано множество, для которого необходимо выполнять только `сборку` без запуска тестов - для каждого пресета, содержащего в своём названии _trace_, тесты запускаться не будут. 

# Pre-commit hooks

Для использования pre-commit hooks необходимо установить `pre-commit`:
```shell
pip install pre-commit
```

Далее необходимо создать файл конфигурации `.pre-commit-config.yaml`

Затем, необходимо установить описанные в конфигурационном файле скрипты:
```shell
pre-commit install
```

После установки скрипты будут запускаться каждый раз при совершении коммита.
