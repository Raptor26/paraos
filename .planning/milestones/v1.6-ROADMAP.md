### 🚧 v1.6 paraos::jthread scheduler control (In Planning)

**Milestone Goal:** Добавить кроссплатформенное управление планировщиком в `paraos::jthread`, эмулировать семантику FreeRTOS на PC и унифицировать `jthread`-тесты.

#### Phase 24: FreeRTOS scheduler API ✅
**Goal**: `paraos::jthread` делегирует управление планировщиком FreeRTOS в `vTaskStartScheduler()` / `vTaskEndScheduler()`.
**Depends on**: Phase 23
**Requirements**: SCHED-01, SCHED-02, SCHED-03, SCHED-07
**Success Criteria** (what must be TRUE):
  1. Разработчик может вызвать `paraos::jthread::start_scheduler()` в FreeRTOS-приложении.
  2. `paraos::jthread::is_scheduler_running()` возвращает корректное состояние до и после запуска планировщика.
  3. `paraos::Thread` не изменился; `paraos::jthread` не использует `paraos::Thread`.
**Plans**: 2/2 complete

Plans:
- [x] 24-01: Добавить `start_scheduler()`, `end_scheduler()` и `is_scheduler_running()` в `port_freertos/paraos_jthread.hpp`
- [x] 24-02: Проверить компиляцию `freertos_debug_clang` и `freertos_debug_gcc`

#### Phase 25: PC scheduler state and gating ✅
**Goal**: PC-порт эмулирует семантику FreeRTOS: потоки ждут `start_scheduler()` и останавливаются по `end_scheduler()`.
**Depends on**: Phase 24
**Requirements**: SCHED-04, SCHED-05, SCHED-06
**Success Criteria** (what must be TRUE):
  1. Созданные до `start_scheduler()` потоки не выполняются до её вызова.
  2. После `start_scheduler()` все ожидающие потоки начинают выполнение.
  3. `end_scheduler()` останавливает и объединяет все активные `paraos::jthread`.
  4. `is_scheduler_running()` возвращает `false` после `end_scheduler()`.
**Plans**: 3/3 complete

Plans:
- [x] 25-01: Добавить `SchedulerState`, реестр контекстов и гейтинг запуска в `port_pc/paraos_jthread.hpp`
- [x] 25-02: Обновить конструктор/деструктор, move-операции и `request_stop`/`join` для работы с реестром
- [x] 25-03: Реализовать `start_scheduler()`, `end_scheduler()` и `is_scheduler_running()` для PC

#### Phase 26: Test unification ✅
**Goal**: `jthread`-тесты используют единый кроссплатформенный паттерн без `std::_Exit()` и платформенных ветвей.
**Depends on**: Phase 25
**Requirements**: TEST-01, TEST-02, TEST-03, TEST-04
**Success Criteria** (what must be TRUE):
  1. `port_tests/test_jthread_basic.cpp` не содержит `std::_Exit()` и единообразен для PC и FreeRTOS.
  2. Обновлённые тесты используют `paraos::sleep_for(std::chrono::milliseconds{...})`.
  3. Контейнерные multithread-тесты вызывают `paraos::jthread::start_scheduler()` и не используют `std::_Exit()`.
  4. `test_jthread_basic` проходит на PC.
**Plans**: 7/7 complete

Plans:
- [x] 26-01: Обновить PC end_scheduler и переписать `port_tests/test_jthread_basic.cpp`
- [x] 26-02: Обновить `containers/tests/test_queue_blocking_mpsc.cpp`
- [x] 26-03: Обновить `containers/tests/test_queue_blocking_spmc.cpp`
- [x] 26-04: Обновить `containers/tests/test_queue_blocking_mpmc.cpp`
- [x] 26-05: Обновить `containers/tests/test_multi_ringbuff_mpmc.cpp`
- [x] 26-06: Обновить `containers/tests/test_message_multithread_many_producer_many_consumers.cpp`
- [x] 26-07: Собрать и запустить унифицированные тесты на PC

#### Phase 27: Build and static analysis verification ✅
**Goal**: Все PC-пресеты собираются, запускаются и проходят тесты; `*_clang_tidy` пресеты не дают новых предупреждений; FreeRTOS-пресеты собираются и их тесты корректно завершаются.
**Depends on**: Phase 26
**Requirements**: BLD-01, BLD-02, BLD-03
**Success Criteria** (what must be TRUE):
  1. `pc_debug_clang` и `pc_debug_gcc` собираются, запускаются и проходят `ctest --timeout 20` без регрессий.
  2. `test_jthread_basic` и обновлённые контейнерные multithread-тесты успешно проходят с таймаутом 20 секунд; тест, не завершившийся за 20 секунд, считается проваленным.
  3. `pc_debug_gcc_clang_tidy` собирается и не сообщает новых предупреждений от кода `paraos::jthread`.
  4. `freertos_debug_clang` и `freertos_debug_gcc` собираются; все тесты, включая `test_jthread_basic` и контейнерные multithread-тесты, корректно завершаются (не висят и не падают по таймауту).
**Plans**: 6/6 complete

Plans:
- [x] 27-01: Собрать `pc_debug_clang` / `pc_debug_gcc`
- [x] 27-02: Запустить `ctest --timeout 20` для `pc_debug_clang` / `pc_debug_gcc` и убедиться, что все тесты проходят
- [x] 27-03: Уделить особое внимание `test_jthread_basic` и обновлённым контейнерным multithread-тестам — они должны завершаться в пределах 20 секунд
- [x] 27-04: Собрать `pc_debug_gcc_clang_tidy` и убедиться в отсутствии новых предупреждений
- [x] 27-05: Собрать `freertos_debug_clang` / `freertos_debug_gcc`
- [x] 27-06: Запустить FreeRTOS-тесты, включая `test_jthread_basic` и контейнерные multithread-тесты, и убедиться, что они корректно завершаются без зависаний
