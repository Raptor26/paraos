# Requirements: PARAOS — Modernize container tests on std-like primitives

**Defined:** 2026-06-22
**Core Value:** Кроссплатформенная переносимость PARAOS сохраняется: код, работающий на Linux/Windows/FreeRTOS, продолжает работать, а новая macOS-разработка ведётся на равных с остальными платформами, включая статический анализ clang-tidy.

## v1 Requirements

### Analysis

- [ ] **ANL-01**: Проведён анализ каждого multithread-теста в `containers/tests/` на используемые legacy-примитивы (`paraos::Thread`, `paraos::Mutex`, `paraos::SemaphoreBinary` / `paraos::SemaphoreCounting`) и определена возможность их замены на std-like обёртки.
- [ ] **ANL-02**: Зафиксирован перечень API-различий между legacy- и std-like примитивами, которые влияют на переписывание тестов (например, `ThreadAttr`, `Finished()`, `StartScheduler`, `DeleteAll`, `try_acquire_for`, `stop_token`).
- [ ] **ANL-03**: Определён минимальный набор доработок `port_freertos`, необходимых для единообразного использования `paraos::jthread`, `paraos::mutex` и `paraos::counting_semaphore` в тестах контейнеров.

### Threading

- [ ] **THR-01**: Тесты `test_queue_blocking_spmc.cpp`, `test_queue_blocking_mpsc.cpp`, `test_queue_blocking_mpmc.cpp` переведены с `paraos::Thread` + `thread_delegate_type` на `paraos::jthread` (с `ThreadAttr`, если нужно задать приоритет/стек).
- [ ] **THR-02**: Тест `test_multi_ringbuff_mpmc.cpp` переведён с `paraos::Thread` на `paraos::jthread` с сохранением логики множества producer/consumer.
- [ ] **THR-03**: Тест `test_message_multithread_many_producer_many_consumers.cpp` переведён с `paraos::Thread` на `paraos::jthread` с сохранением producer/consumer сценария.
- [ ] **THR-04**: Устранены вызовы `paraos::Thread::StartScheduler()` / `DeleteAll()` / `Exit()` / `Finished()`, неактуальные для `paraos::jthread`; финализация тестов реализована через `request_stop()` / `join()` или `std::_Exit()` для FreeRTOS-режима.

### Synchronization

- [ ] **SYNC-01**: Legacy `paraos::Mutex` и `MutexGuard` в затронутых тестах заменены на `paraos::mutex` + `std::lock_guard` / `std::unique_lock` там, где это повышает читаемость и безопасность.
- [ ] **SYNC-02**: Legacy `paraos::SemaphoreBinary` / `paraos::SemaphoreCounting` в затронутых тестах заменены на `paraos::binary_semaphore` / `paraos::counting_semaphore` при наличии семантически подходящих точек использования.
- [ ] **SYNC-03**: Обеспечена корректная работа `std::lock_guard<paraos::mutex>` и `std::unique_lock<paraos::mutex>` на всех портах (PC, Unix, Windows, FreeRTOS).

### FreeRTOS uniform behavior

- [ ] **FR-01**: В `port_freertos` добавлены или доработаны вспомогательные функции/методы std-like примитивов, необходимые для единообразного тестирования (например, получение имени потока, корректная обработка `stop_token` при раннем выходе, совместимость с `std::chrono`).
- [ ] **FR-02**: Поведение `paraos::jthread::join()` и `request_stop()` на FreeRTOS не приводит к deadlock / use-after-free в сценариях тестов контейнеров.
- [ ] **FR-03**: `paraos::counting_semaphore::release(N)` и `try_acquire_for` на FreeRTOS корректно работают с `std::chrono` таймаутами в многопоточных тестах.

### Build & verification

- [ ] **BLD-01**: Все затронутые multithread-тесты компилируются в PC-пресетах (`pc_debug_clang`, `pc_debug_gcc`) и проходят `ctest`.
- [ ] **BLD-02**: Все затронутые multithread-тесты компилируются в FreeRTOS-пресетах (`freertos_debug_clang`, `freertos_debug_gcc`) без новых ошибок компиляции.
- [ ] **BLD-03**: `*_clang_tidy` пресеты не получают новых предупреждений от изменённых тестов и дополнений `port_freertos`.
- [ ] **BLD-04**: Сохранена возможность запуска стресс-тестов (`ctest -L stress`) для переведённых multithread-тестов.

## v2 Requirements

## Out of Scope

| Feature | Reason |
|---------|--------|
| Изменение реализации самих контейнеров (`paraos_queue_blocking.hpp`, `paraos_message_buffer.hpp`, `paraos_multi_ringbuff.hpp`) | Цель — обновить тесты, а не менять контейнеры. |
| Удаление или депрекация legacy-примитивов `paraos::Thread`, `paraos::Mutex`, `paraos::SemaphoreBinary` | Legacy API остаётся рабочим; std-like API добавляется рядом. |
| Переписывание тестов вне `containers/tests/` (port_tests, extra/tests, port_unix/tests) | Веха ограничена контейнерами по согласованию. |
| Полноценный runtime-запуск FreeRTOS-тестов на macOS POSIX-симуляторе | Известное ограничение среды; компиляция и базовые проверки construct/destruct возможны. |
| Добавление новых функциональных возможностей в std-like примитивы сверх минимума, необходимого для тестов | Не хотим раздувать веху. |
