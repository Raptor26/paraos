# Requirements: PARAOS

**Defined:** 2026-06-22
**Core Value:** Кроссплатформенная переносимость PARAOS сохраняется: код, работающий на Linux/Windows/FreeRTOS, продолжает работать, а новая macOS-разработка ведётся на равных с остальными платформами, включая статический анализ clang-tidy.

## v1 Requirements

### Scheduler API

- [x] **SCHED-01**: `paraos::jthread` предоставляет статические методы `start_scheduler()`, `end_scheduler()` и `is_scheduler_running()` для всех портов.
- [x] **SCHED-02**: FreeRTOS-порт делегирует `start_scheduler()` в `vTaskStartScheduler()` и `end_scheduler()` в `vTaskEndScheduler()`.
- [x] **SCHED-03**: FreeRTOS-порт `is_scheduler_running()` возвращает `xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED`.
- [x] **SCHED-04**: PC-порт эмулирует семантику FreeRTOS: потоки, созданные до `start_scheduler()`, не выполняются до её вызова.
- [x] **SCHED-05**: PC-порт `end_scheduler()` останавливает и объединяет все активные `paraos::jthread`, после чего возвращает управление.
- [x] **SCHED-06**: PC-порт `is_scheduler_running()` возвращает `true` только после `start_scheduler()` и до вызова `end_scheduler()`.
- [x] **SCHED-07**: `paraos::Thread` остаётся неизменным; `paraos::jthread` не зависит от `paraos::Thread`.

### Tests

- [x] **TEST-01**: `port_tests/test_jthread_basic.cpp` переписан без `std::_Exit()` и без платформенных ветвей в тестовой логике.
- [x] **TEST-02**: `port_tests/test_jthread_basic.cpp` использует `paraos::sleep_for(std::chrono::milliseconds{...})` вместо `paraos::Thread::DelayMs()`.
- [x] **TEST-03**: Контейнерные multithread-тесты (`test_multi_ringbuff_mpmc`, `test_message_multithread_many_producer_many_consumers`, `test_queue_blocking_mpsc/spmc/mpmc`) явно вызывают `paraos::jthread::start_scheduler()`.
- [x] **TEST-04**: Контейнерные multithread-тесты больше не используют `std::_Exit()` для завершения.

### Build & Static Analysis

- [x] **BLD-01**: Пресеты `pc_debug_clang` и `pc_debug_gcc` собираются и проходят `ctest` без регрессий.
- [x] **BLD-02**: Пресеты `*_clang_tidy` собираются без новых предупреждений от кода `paraos::jthread`.
- [x] **BLD-03**: Пресеты `freertos_debug_clang` и `freertos_debug_gcc` компилируются.

## v2 Requirements

Deferred to future release.

### Thread API removal

- **THR-REM-01**: Удаление legacy `paraos::Thread` после полной миграции потребителей на `paraos::jthread`.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Изменение `paraos::Thread` API | Требование SCHED-07 — `jthread` управляет планировщиком самостоятельно. |
| Миграция `extra/` и production-кода на `paraos::jthread` | Только тесты и публичный API `jthread` в текущей вехе. |
| Runtime-запуск FreeRTOS-тестов на macOS POSIX-симуляторе | Environment limitation, задокументировано в STATE.md. |
| Новые примитивы синхронизации | Веха фокусируется на управлении планировщиком `jthread`. |
