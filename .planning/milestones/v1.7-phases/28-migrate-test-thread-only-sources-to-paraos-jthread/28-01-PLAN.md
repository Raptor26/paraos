# Plan 28-01: Migrate `test_thread_only_*` sources to `paraos::jthread`

## Objective

Rewrite the four standalone `port_tests/test_thread_only_*.cpp` tests from the
legacy `paraos::Thread` API to the modern `paraos::jthread` API. Preserve the
original test intent (thread creation, completion counting, global/static/stack
lifetime, and multi-thread-per-object synchronization) while adopting the
unified cross-platform lifecycle pattern already proven in
`test_jthread_basic.cpp` and the container multithread tests.

## Must-Haves

- [ ] MH-01: `test_thread_only_global.cpp` uses `paraos::jthread` for all
  threads; no `paraos::Thread` objects or `RegisterDelegate` calls remain.
- [ ] MH-02: `test_thread_only_static.cpp` uses `paraos::jthread` for all
  `static` thread objects; no `paraos::Thread` remains.
- [ ] MH-03: `test_thread_only_stack.cpp` stores worker threads in
  `std::vector<paraos::jthread>` and removes all `new`/`delete` of thread
  objects.
- [ ] MH-04: `test_thread_only_stack_with_multiple_threads.cpp` stores thread
  groups in an RAII container and removes `new`/`delete`, `Finished(this)`, and
  self-deletion.
- [ ] MH-05: None of the four files call `paraos::Thread::StartScheduler()`,
  `paraos::Thread::Exit()`, `paraos::Thread::DeleteAll()`, or `std::_Exit()`.
- [ ] MH-06: All four files use the unified lifecycle:
  - `main()` creates worker threads and a `stopper` thread, then calls
    `paraos::jthread::start_scheduler()`.
  - The `stopper` thread polls the completion condition and calls
    `NotifySchedulerEnded()`.
  - `IdleHook()` waits for the scheduler-ended signal, performs the final
    success check, and calls `(void)paraos::jthread::end_scheduler()`.
  - For FreeRTOS: `#if PARAOS_LIKE_FREERTOS` assigns
    `paraos::freertos_idle_fnc_ptr = IdleHook;` before `start_scheduler()`.
  - `main()` calls `IdleHook()` again after `WaitForSchedulerEnded()` so the
    same code path runs on PC.
- [ ] MH-07: `paraos::sleep_for(std::chrono::milliseconds{...})` replaces
  `paraos::Thread::DelayMs()` wherever polling/yielding is needed.
- [ ] MH-08: `PrintDebug` keeps `paraos::CriticalSection` for serialized
  console output.
- [ ] MH-09: No platform-specific `#ifdef` branches remain around test
  termination.
- [ ] MH-10: Each migrated file compiles as C++20 and introduces no new
  clang-tidy diagnostics.

## Tasks

### Task 1: Add shared scheduler-shutdown helpers to each file

**read_first:**
- `port_tests/test_jthread_basic.cpp`
- `containers/tests/test_queue_blocking_mpmc.cpp`

**details (repeat for all four target files):**
1. Add includes as needed: `<condition_variable>`, `<mutex>`, `<chrono>`,
   `<vector>`, `<memory>`, `<atomic>`, `<cstdlib>`, `<iostream>`, `<string>`.
2. Keep the existing `PrintDebug` macro, preserving `paraos::CriticalSection`.
3. In the anonymous namespace add:
   - `std::mutex g_done_mtx;`
   - `std::condition_variable g_done_cv;`
   - `bool g_scheduler_ended{false};`
   - `void NotifySchedulerEnded()` — sets `g_scheduler_ended = true` under
     `g_done_mtx` and notifies `g_done_cv`.
   - `void WaitForSchedulerEnded()` — waits on `g_done_cv` until
     `g_scheduler_ended` is true.
   - `void IdleHook()` — calls `WaitForSchedulerEnded()`, performs the final
     assertion, then `(void)paraos::jthread::end_scheduler();`.

### Task 2: Migrate `test_thread_only_global.cpp`

**read_first:**
- `port_tests/test_thread_only_global.cpp`
- `port_pc/paraos_jthread.hpp`

**details:**
1. Replace the four global `paraos::Thread` objects with global
   `paraos::jthread` objects constructed with `paraos::ThreadAttr` and worker
   lambdas.
2. Worker lambdas receive `const paraos::stop_token&`, call `PrintDebug`,
   increment `cnt`, call `DeletedObjectsCnt()`, and return.
3. Replace the `check_test_complete_and_exit` watcher with a local `stopper`
   `paraos::jthread` in `main()` that polls until `cnt >= EXPECTED_THREADS`,
   then calls `NotifySchedulerEnded()`.
4. Remove all `etl::delegate::create<...>` registrations and the helper
   functions `ProcessingOne`, `ProcessingTwo`, `ProcessingThree`,
   `ExitFromTest`.
5. In `main()`:
   - Create the `stopper` thread.
   - Set `#if PARAOS_LIKE_FREERTOS` `paraos::freertos_idle_fnc_ptr = IdleHook;`.
   - Call `paraos::jthread::start_scheduler();`.
   - Call `WaitForSchedulerEnded();`.
6. After the inner scope, call `IdleHook();` and `return 0;`.
7. Remove `paraos::Thread::StartScheduler()` and `paraos::Thread::DeleteAll()`.

### Task 4: Migrate `test_thread_only_stack.cpp`

**read_first:**
- `port_tests/test_thread_only_stack.cpp`

**details:**
1. Remove the `MyThreadDynamic` class and its self-deletion logic.
2. In `main()`, create `std::vector<paraos::jthread> threads;`.
3. Loop `for (std::size_t i = 0; i < EXPECTED_THREADS; ++i)`:
   - Build a `paraos::ThreadAttr` with a unique `thread_name`.
   - `threads.emplace_back(attr, [i](const paraos::stop_token& /*token*/) { ... });`

4. Add a local `stopper` thread that polls until
   `deleted_objects_cnt >= EXPECTED_THREADS`, then calls
   `NotifySchedulerEnded()`.
5. Use the same unified lifecycle pattern.
6. Remove all `new`/`delete`, `Finished()`, `Thread::Exit()`, and `std::_Exit()`.

### Task 5: Migrate `test_thread_only_stack_with_multiple_threads.cpp`

**read_first:**
- `port_tests/test_thread_only_stack_with_multiple_threads.cpp`
- `port_pc/paraos_semaphore_std.hpp`

**details:**
1. Replace `MyThreadDynamic` with a `MyThreadGroup` struct that owns three
   `paraos::jthread` objects and two `paraos::binary_semaphore` objects:
   - `paraos::jthread thread_one_;`
   - `paraos::jthread thread_two_;`
   - `paraos::jthread thread_dynamic_;`
   - `paraos::binary_semaphore is_thread_one_complete_work_{0};`
   - `paraos::binary_semaphore is_dynamic_thread_complete_work_{0};`
2. The constructor takes a thread name and creates the three `jthread` objects
   with lambdas capturing `this`.
3. Because `paraos::binary_semaphore` is non-movable, store groups in
   `std::vector<std::unique_ptr<MyThreadGroup>>`.
4. `thread_one` lambda: print, signal `is_thread_one_complete_work_`, call
   `DeletedObjectsCnt()`, return.
5. `thread_dynamic` lambda: print, signal `is_dynamic_thread_complete_work_`,
   call `DeletedObjectsCnt()`, return.
6. `thread_two` lambda: take both semaphores, print, call `DeletedObjectsCnt()`,
   return.
7. In `main()`, create `EXPECTED_THREADS` groups and push them into the vector.
8. Add a `stopper` thread that polls until
   `deleted_objects_cnt >= EXPECTED_THREADS * 2` (matching the original
   two-deletions-per-group invariant), then calls `NotifySchedulerEnded()`.
9. Use the same unified lifecycle pattern.
10. Remove all `new`/`delete`, `Finished(this)`, `Thread::Exit()`, and
    `std::_Exit()`.

  without new clang-tidy warnings.
- Each standalone executable runs on PC, prints a success indicator, and exits
  cleanly.
- `freertos_debug_clang` and `freertos_debug_gcc` compile the four targets
  (runtime execution is environment-limited on the macOS POSIX simulator).
- No occurrences of `paraos::Thread::StartScheduler`, `paraos::Thread::Exit`,
  `paraos::Thread::DeleteAll`, or `std::_Exit` remain in the four files.

## Risks

- **Global/static destructor ordering:** global and `static` `paraos::jthread`
  objects are destroyed after `main()` returns. If `end_scheduler()` is not
  called before `main()` exits, the destructors may try to join running
  threads. Ensure `IdleHook()` always runs and stops the scheduler.
- **C++20 compile-feature timing:** `port_tests/CMakeLists.txt` still lists
  `cxx_std_17` for these targets, but `paraos_jthread.hpp` requires C++20.
  Build verification in this phase may need a temporary local CMake change;
  the formal update is Phase 29.
- **Non-movable semaphore:** `paraos::binary_semaphore` is non-movable, forcing
  `std::unique_ptr<MyThreadGroup>` for the multi-thread test. This still
  satisfies IDIO-01 (RAII container, no manual `delete`), but should be
  documented if challenged.
- **Static local `jthread` destruction:** `const static paraos::jthread` objects
  inside `main()` blocks are destroyed in reverse construction order after the
  block exits. Keep them inside the same scope as the `stopper` and lifecycle
  helpers so the scheduler is stopped before destructors run.
