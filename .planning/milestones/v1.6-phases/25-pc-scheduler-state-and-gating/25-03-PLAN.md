# Plan 25-03: Verify PC scheduler gating builds

## Objective

Confirm that the reworked PC `paraos::jthread` compiles cleanly under the PC
Clang and GCC presets and that `test_jthread_basic` still compiles.

## Must-Haves

- [ ] MH-01: `pc_debug_clang` preset configures and builds `paraos` target.
- [ ] MH-02: `pc_debug_gcc` preset configures and builds `paraos` target.
- [ ] MH-03: `test_jthread_basic` target compiles under `pc_debug_clang`.
- [ ] MH-04: `test_jthread_basic` target compiles under `pc_debug_gcc`.
- [ ] MH-05: No new compiler warnings are introduced by the scheduler gating.

## Tasks

### Task 1: Build PC library with Clang

**details:**
1. Configure:
   ```bash
   cmake --preset pc_debug_clang
   ```
2. Build:
   ```bash
   cmake --build build/pc_debug_clang/ --target paraos -j4
   ```

### Task 2: Build PC library with GCC

**details:**
1. Configure:
   ```bash
   cmake --preset pc_debug_gcc
   ```
2. Build:
   ```bash
   cmake --build build/pc_debug_gcc/ --target paraos -j4
   ```

### Task 3: Compile jthread test with both toolchains

**details:**
1. Build `test_jthread_basic` for both presets.
2. Capture the output.

### Task 4: Capture build log

**details:**
1. Save combined output to `.planning/phases/25-pc-scheduler-state-and-gating/25-03-build.log`.

## Verification

- All four builds complete with exit code 0.
- Build log is committed as evidence.

## Risks

- `test_jthread_basic` will likely fail at runtime because it expects immediate thread start; that is expected and fixed in Phase 26. This plan only verifies compilation.
- PC presets on macOS use `port_unix`; ensure POSIX timers are available on the build host.
