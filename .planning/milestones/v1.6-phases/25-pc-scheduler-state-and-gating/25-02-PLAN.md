# Plan 25-02: Wire gating into MakeThread and implement scheduler methods

## Objective

Connect the per-thread gate and registry from 25-01 to the actual thread
launch path and implement `start_scheduler()`, `end_scheduler()`, and
`is_scheduler_running()` for the PC port.

## Must-Haves

- [ ] MH-01: `MakeThread()` stores attributes in `context_.attr`, creates `std::jthread`, and the worker lambda waits on `WaitForGate(&context_)` before invoking the user callable.
- [ ] MH-02: If the gate opens with `should_run=false`, the worker exits without executing user code.
- [ ] MH-03: Templated constructors open the gate immediately if scheduler is already running or already stopped; otherwise leave it closed.
- [ ] MH-04: `start_scheduler()` transitions state from `kNotStarted` to `kRunning`, opens all waiting gates with `should_run=true`, and is idempotent/no-op after stop.
- [ ] MH-05: `end_scheduler()` transitions state from `kRunning` to `kStopped`, opens all waiting gates with `should_run=false`, requests stop on every active thread, joins every active thread, and returns `true`; returns `false` if not running.
- [ ] MH-06: `is_scheduler_running()` returns `s_scheduler_state == kRunning`.
- [ ] MH-07: Doxygen comments warn that `end_scheduler()` must not be called from a worker thread.

## Tasks

### Task 1: Gate the worker thread in MakeThread()

**read_first:**
- `port_pc/paraos_jthread.hpp`

**details:**
1. In `MakeThread()`, after assigning `context_.thread = std::jthread(...)`, modify the lambda body:
   ```cpp
   WaitForGate(&context_);
   if (!context_.should_run) {
     return;
   }
   std::invoke(...);
   ```
2. Remove the old `ApplyAttr()` call location if it needs to move; keep `ApplyAttr()` implementation unchanged.

**acceptance_criteria:**
1. Worker lambda compiles.
2. `WaitForGate` is called before user callable.

### Task 2: Initialize gate state in constructors

**read_first:**
- `port_pc/paraos_jthread.hpp`

**details:**
1. At the end of each templated constructor (after `MakeThread` returns), add logic to open the gate if scheduler is not `kNotStarted`:
   ```cpp
   {
     std::lock_guard lock{s_registry_mutex};  // already registered
     if (s_scheduler_state != SchedulerState::kNotStarted) {
       OpenGate(&context_, s_scheduler_state == SchedulerState::kRunning);
     }
   }
   ```
2. Ensure this happens while `&context_` is already in the registry.

**acceptance_criteria:**
1. Threads created while scheduler is running start immediately.
2. Threads created after scheduler stopped exit immediately.

### Task 3: Implement start_scheduler(), end_scheduler(), is_scheduler_running()

**read_first:**
- `port_pc/paraos_jthread.hpp`
- `port_freertos/paraos_jthread.hpp`

**details:**
1. Add public static methods:
   ```cpp
   static void start_scheduler();
   [[nodiscard]] static bool is_scheduler_running() noexcept;
   [[nodiscard]] static bool end_scheduler();
   ```
2. Implement `start_scheduler()`:
   - Atomically exchange state from `kNotStarted` to `kRunning`; if not `kNotStarted`, return.
   - Snapshot registry under `s_registry_mutex`.
   - For each context in snapshot, `OpenGate(ctx, true)`.
3. Implement `end_scheduler()`:
   - Atomically exchange state from `kRunning` to `kStopped`; if not `kRunning`, return `false`.
   - Snapshot registry under `s_registry_mutex`.
   - For each context in snapshot, `OpenGate(ctx, false)`.
   - For each context, `ctx->thread.request_stop()`.
   - For each context, `ctx->thread.join()`.
   - Return `true`.
4. Implement `is_scheduler_running()`:
   - Return `s_scheduler_state.load() == SchedulerState::kRunning`.

**acceptance_criteria:**
1. All three methods compile.
2. `end_scheduler()` returns correct boolean.
3. State transitions are atomic.

### Task 4: Update destructor to release the private gate

**read_first:**
- `port_pc/paraos_jthread.hpp`

**details:**
1. In the destructor, before joining a joinable thread, release its private gate with `should_run=false` so a waiting worker does not deadlock:
   ```cpp
   if (joinable()) {
     request_stop();
     {
       std::lock_guard lock{context_.gate_mtx};
       context_.should_run = false;
       context_.gate_open = true;
     }
     context_.gate_cv.notify_one();
     join();
   }
   ```

**acceptance_criteria:**
1. Destroying a jthread whose worker is waiting for the scheduler does not hang.

## Verification

- `pc_debug_clang` and `pc_debug_gcc` presets configure and build the `paraos` target without errors.
- `test_jthread_basic` compiles (runtime behavior is fixed in Phase 26).

## Risks

- Holding the registry snapshot while joining threads means the snapshot must not include contexts whose owning `jthread` is destroyed during iteration. Caller must ensure all `jthread` objects outlive `end_scheduler()`.
- `end_scheduler()` self-deadlock if called from a worker thread; documented in comments.
