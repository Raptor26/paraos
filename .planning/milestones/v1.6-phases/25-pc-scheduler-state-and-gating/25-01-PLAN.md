# Plan 25-01: Add SchedulerState, registry, and per-thread gate to PC jthread

## Objective

Introduce the scheduler-state machinery and per-thread gating into
`port_pc/paraos_jthread.hpp` without yet wiring it into `MakeThread()` or the
scheduler methods. This plan lays the foundation that 25-02 will use.

## Must-Haves

- [ ] MH-01: `SchedulerState` enum with `kNotStarted`, `kRunning`, `kStopped`.
- [ ] MH-02: Static atomic `s_scheduler_state` initialized to `kNotStarted`.
- [ ] MH-03: Static registry `s_registry` (e.g. `std::unordered_set<Context*>`) guarded by `s_registry_mutex`.
- [ ] MH-04: `Context` struct contains `std::jthread thread`, `ThreadAttr attr`, gate mutex, gate CV, `bool gate_open`, and `bool should_run`.
- [ ] MH-05: Helper `OpenGate(Context*, bool should_run)` opens a context's gate thread-safely.
- [ ] MH-06: Helper `WaitForGate(Context*)` blocks until the gate is open.
- [ ] MH-07: The PC `jthread` class stores a single `Context context_` member instead of separate `thread_`/`attr_`.
- [ ] MH-08: Default constructor added.
- [ ] MH-09: Move constructor and move assignment update the registry (`erase` source, `insert` destination).
- [ ] MH-10: Constructor registers `&context_` in the registry; destructor unregisters it.
- [ ] MH-11: Existing public methods (`join`, `joinable`, `request_stop`) compile and delegate to `context_.thread`.

## Tasks

### Task 1: Define scheduler state, registry, and gate helpers

**read_first:**
- `port_pc/paraos_jthread.hpp`

**details:**
1. After `namespace paraos {`, add:
   - `enum class SchedulerState { kNotStarted, kRunning, kStopped };`
   - `static std::atomic<SchedulerState> s_scheduler_state{SchedulerState::kNotStarted};`
   - `static std::mutex s_registry_mutex;`
   - `static std::unordered_set<Context*> s_registry;`
   - Helper functions `OpenGate` and `WaitForGate` (declared; `Context` is defined later inside `jthread`).
2. Because `Context` is a nested private type, declare the helpers as `static` free functions taking `jthread::Context*` or forward-declare a public `Context` struct. Simpler: make `Context` a public nested struct and helpers free functions in `namespace paraos`.

**acceptance_criteria:**
1. Header compiles after declarations are added.
2. `s_registry` accesses are always guarded by `s_registry_mutex`.

### Task 2: Replace members with Context and update special members

**read_first:**
- `port_pc/paraos_jthread.hpp`
- `port_freertos/paraos_jthread.hpp`

**details:**
1. Replace private members `ThreadAttr attr_{}; std::jthread thread_;` with `Context context_;`.
2. Define `Context` (public or private nested struct) with fields listed in MH-04.
3. Add `jthread() noexcept = default;`.
4. Update move constructor/assignment and destructor to use `context_` and update the registry.
5. Keep the templated constructors unchanged except for the member rename; they still call `MakeThread()`.
6. Update `joinable()`, `join()`, and `request_stop()` to use `context_.thread`.

**acceptance_criteria:**
1. PC `jthread` header compiles on its own.
2. `Context` is movable.
3. Registry is updated correctly on move.

## Verification

- `pc_debug_clang` and `pc_debug_gcc` presets configure and build the `paraos` target without errors.

## Risks

- Moving from `thread_`/`attr_` to `context_` is a wide refactor; all member functions must be updated consistently.
- Helper functions referencing a nested private type may need the type to be public or need friend declarations.
