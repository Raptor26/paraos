# Plan 24-01: Add scheduler control methods to FreeRTOS jthread

## Objective

Add static scheduler-control methods to `paraos::jthread` in the FreeRTOS port:
`start_scheduler()`, `end_scheduler()`, and `is_scheduler_running()`.
The methods delegate to FreeRTOS scheduler API and add safety checks
described in the phase context.

## Must-Haves

- [ ] MH-01: `paraos::jthread::start_scheduler()` is a public static `void` method that calls `vTaskStartScheduler()`.
- [ ] MH-02: `start_scheduler()` guards against repeated calls with `PARAOS_CHECK_ASSERT(xTaskGetSchedulerState() == taskSCHEDULER_NOT_STARTED)`.
- [ ] MH-03: `paraos::jthread::is_scheduler_running()` is a public static `bool` method returning `xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED`.
- [ ] MH-04: `paraos::jthread::end_scheduler()` is a public static `bool` method.
- [ ] MH-05: `end_scheduler()` returns `false` without calling `vTaskEndScheduler()` when the scheduler is not running.
- [ ] MH-06: `end_scheduler()` calls `vTaskEndScheduler()` and returns `true` when the scheduler is running.
- [ ] MH-07: Doxygen comments include `@note`/`@warning` documenting FreeRTOS POSIX/macOS runtime limitations.
- [ ] MH-08: No dependency on `paraos::Thread` is introduced.
- [ ] MH-09: Header-only implementation is preserved; no new source files.

## Tasks

### Task 1: Add scheduler methods

**read_first:**
- `port_freertos/paraos_jthread.hpp`
- `port_freertos/paraos_thread.hpp`
- `paraos_check.h`

**details:**
1. Add `#include "paraos_check.h"` if not already present.
2. Add three public static methods to `paraos::jthread` after `joinable()`:
   - `static void start_scheduler()` — asserts scheduler not started, then `vTaskStartScheduler()`.
   - `static bool is_scheduler_running()` — returns scheduler state check.
   - `static bool end_scheduler()` — checks scheduler running, calls `vTaskEndScheduler()` if so, returns result.
3. Write Doxygen comments matching project style, including runtime limitation notes.

**acceptance_criteria:**
1. The three methods compile under the FreeRTOS presets.
2. No `paraos::Thread` symbols are referenced in `port_freertos/paraos_jthread.hpp`.
3. `PARAOS_CHECK_ASSERT` is used for the repeated-call guard.

## Verification

- `grep` confirms the three static methods exist in `port_freertos/paraos_jthread.hpp`.
- Build verification is performed by plan 24-02.

## Risks

- `vTaskEndScheduler()` requires a valid `vPortEndScheduler()` in the target FreeRTOS port; this is caller responsibility and documented in comments.
- FreeRTOS POSIX simulator on macOS cannot run these methods to completion; validation is build-only on this host.
