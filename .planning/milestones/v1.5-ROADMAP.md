### ✅ v1.5 Modernize container tests on std-like primitives (Shipped 2026-06-22)

**Milestone Goal:** Перевести многопоточные тесты контейнеров в `containers/tests/` с legacy-примитивов `paraos::Thread` / `paraos::Mutex` / `paraos::SemaphoreBinary` на современные `paraos::jthread`, `paraos::mutex`, `paraos::counting_semaphore` / `paraos::binary_semaphore`, сохранив работоспособность на PC и FreeRTOS.

- [x] **Phase 19: Inventory & gap analysis** — Audit multithread container tests, identify replacements, list FreeRTOS gaps
- [x] **Phase 20: Migrate thread primitives in container tests** — Replace `paraos::Thread` with `paraos::jthread` across multithread tests
- [x] **Phase 21: Migrate synchronization primitives in container tests** — Replace `paraos::Mutex` / `SemaphoreBinary` with `paraos::mutex` / `paraos::*_semaphore`
- [x] **Phase 22: FreeRTOS std-like primitives hardening** — Add helper APIs / fixes needed for uniform behavior
- [x] **Phase 23: Build, tests and static analysis** — Verify PC and FreeRTOS presets, clang-tidy, stress tests

## Phase Details

### Phase 19: Inventory & gap analysis

**Goal**: Понять, какие legacy-примитивы используются в multithread-тестах `containers/tests/`, куда их можно заменить на std-like, и какие доработки `port_freertos` для этого понадобятся.
**Depends on**: Phase 18
**Requirements**: ANL-01, ANL-02, ANL-03
**Success Criteria** (what must be TRUE):

  1. Для каждого multithread-теста из `containers/tests/` зафиксирован список используемых legacy-примитивов и предложена замена.
  2. Определены API-различия между `paraos::Thread` и `paraos::jthread`, критичные для переписывания тестов.
  3. Составлен перечень необходимых доработок `port_freertos` для единообразного поведения std-like примитивов.

**Plans**: 1 — `19-PLAN.md`

### Phase 20: Migrate thread primitives in container tests

**Goal**: Заменить `paraos::Thread`, `thread_delegate_type`, `RegisterDelegate`, `Finished`, `StartScheduler`, `DeleteAll`, `Exit` на `paraos::jthread` во всех multithread-тестах `containers/tests/`.
**Depends on**: Phase 19
**Requirements**: THR-01, THR-02, THR-03, THR-04
**Success Criteria** (what must be TRUE):

  1. `test_queue_blocking_spmc.cpp`, `test_queue_blocking_mpsc.cpp`, `test_queue_blocking_mpmc.cpp` используют `paraos::jthread`.
  2. `test_multi_ringbuff_mpmc.cpp` использует `paraos::jthread`.
  3. `test_message_multithread_many_producer_many_consumers.cpp` использует `paraos::jthread`.
  4. Завершение тестов реализовано через `request_stop()` / `join()` или штатный `std::_Exit()` для FreeRTOS, без вызовов `paraos::Thread::StartScheduler()`.

**Plans**: TBD

### Phase 21: Migrate synchronization primitives in container tests

**Goal**: Заменить legacy `paraos::Mutex`, `MutexGuard`, `paraos::SemaphoreBinary` / `SemaphoreCounting` на `paraos::mutex` и `paraos::*_semaphore` в тех местах, где это семантически уместно.
**Depends on**: Phase 20
**Requirements**: SYNC-01, SYNC-02, SYNC-03
**Success Criteria** (what must be TRUE):

  1. `paraos::Mutex` / `MutexGuard` в затронутых тестах заменены на `paraos::mutex` + `std::lock_guard` / `std::unique_lock`.
  2. `paraos::SemaphoreBinary` / `SemaphoreCounting` в затронутых тестах заменены на `paraos::binary_semaphore` / `paraos::counting_semaphore`.
  3. `std::lock_guard<paraos::mutex>` и `std::unique_lock<paraos::mutex>` компилируются и работают на всех портах.

**Plans**: TBD

### Phase 22: FreeRTOS std-like primitives hardening

**Goal**: Внести в `port_freertos` минимальные доработки std-like примитивов, необходимые для корректной работы переписанных тестов контейнеров.
**Depends on**: Phase 19
**Requirements**: FR-01, FR-02, FR-03
**Success Criteria** (what must be TRUE):

  1. В `port_freertos` добавлены или доработаны вспомогательные функции std-like примитивов, требуемые тестами (имена потоков, `stop_token`, `std::chrono`).
  2. `paraos::jthread::join()` и `request_stop()` на FreeRTOS не приводят к deadlock / use-after-free в сценариях тестов.
  3. `paraos::counting_semaphore::release(N)` и `try_acquire_for` на FreeRTOS корректно работают с `std::chrono` таймаутами.

**Plans**: TBD

### Phase 23: Build, tests and static analysis

**Goal**: Убедиться, что все изменённые тесты собираются и проходят на PC, компилируются на FreeRTOS, а `*_clang_tidy` пресеты не получают новых предупреждений.
**Depends on**: Phase 20, Phase 21, Phase 22
**Requirements**: BLD-01, BLD-02, BLD-03, BLD-04
**Success Criteria** (what must be TRUE):

  1. PC-пресеты (`pc_debug_clang`, `pc_debug_gcc`) собираются и проходят `ctest`.
  2. FreeRTOS-пресеты (`freertos_debug_clang`, `freertos_debug_gcc`) компилируются без новых ошибок.
  3. `*_clang_tidy` пресеты не дают новых предупреждений от изменённых файлов.
  4. Стресс-тесты (`ctest -L stress`) остаются доступными для переведённых multithread-тестов.

**Plans**: TBD
