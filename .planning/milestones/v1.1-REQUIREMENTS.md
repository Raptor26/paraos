# Requirements: PARAOS Static Analysis Cleanup

**Defined:** 2026-06-20
**Core Value:** All `*_clang_tidy` CMake presets configure, build, and pass `ctest` on the current macOS hardware without regressing any other platform's build or behavior.

## v1 Requirements

### Tidy Reproduction & Classification

- [x] **REPR-01**: All `*_clang_tidy` presets on macOS are configured and built to capture the full list of clang-tidy warnings
- [x] **REPR-02**: Every reported warning is classified by source file, check name, and whether it is a true positive or false positive

### Core & Header Cleanup

- [x] **CORE-01**: clang-tidy warnings in public core headers (`paraos_*.hpp` / `paraos_*.h`) are fixed or documented as false positives
- [x] **CORE-02**: No public API signatures are changed as a result of core-header cleanup

### port_unix Cleanup

- [x] **PORT-01**: clang-tidy warnings in `port_unix/` sources are fixed or documented as false positives
- [x] **PORT-02**: macOS-specific code paths introduced in v1.0 remain tidy-clean
- [x] **PORT-03**: Linux-specific code paths are left semantically unchanged

### Test & Example Cleanup

- [x] **TEST-01**: clang-tidy warnings in `port_tests/`, `containers/tests/`, `extra/tests/`, `port_unix/tests/`, and executable examples are fixed or documented as false positives
- [x] **TEST-02**: Test logic and assertions are preserved; only style/static-analysis issues are changed

### False-Positive Suppressions

- [x] **SUPP-01**: Every `.clang-tidy` or inline suppression is documented with a rationale explaining why the check is a false positive for PARAOS
- [x] **SUPP-02**: The existing check set in `.clang-tidy` is preserved; no whole-category disables are added without explicit justification

### Regression Avoidance

- [x] **REG-01**: Non-tidy presets (`pc_debug_clang`, `pc_debug_gcc`) continue to configure and build successfully
- [x] **REG-02**: `port_win/` and `port_freertos/` files are not modified in ways that affect their builds
- [x] **REG-03**: Linux, Windows, and FreeRTOS code paths remain semantically unchanged

## v2 Requirements

Deferred to future release.

### CI Integration

- **CI-01**: Add a GitLab CI job that validates macOS presets on a macOS runner
- **CI-02**: Add a GitLab CI job that validates `*_clang_tidy` presets specifically on macOS

### Documentation

- **DOCS-01**: Document macOS-specific build instructions in `README.md`
- **DOCS-02**: Document the static-analysis policy and how to add new suppressions

## Out of Scope

| Feature | Reason |
|---------|--------|
| Adding a new `port_macos/` port | Goal is to clean existing code, not create a new port |
| Runtime performance optimization | Not required for tidy-clean builds |
| Public API redesign | Behavior-preserving cleanup only |
| Physical target/embedded testing | Host PC builds only |
| GitLab CI pipeline modification | Explicitly excluded for this milestone |
| Full `ctest` / stress-test campaigns | Build correctness with clang-tidy is the focus; only sanity smoke checks are needed |
